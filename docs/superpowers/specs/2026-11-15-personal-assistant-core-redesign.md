# ASAKI：个人管家核心体验优化方案

日期：2026-11-15

状态：代码诊断、界面检查与开源调研后的建议稿。本文没有改动业务代码。

## 1. 产品定位

ASAKI 是一个了解用户、协助推进目标的个人管家。典型流程：

> 说出想做的事 → 结合个人情况规划 → 形成长期计划 → 安排今天的任务 → 按时提醒 → 根据反馈调整计划 → 更新个人档案和知识库。

本地 Claude Code、Codex 等 CLI 承担模型推理和工具执行。ASAKI 负责个人数据、目标、任务、提醒、会话管理和界面。先把现有 CLI 的能力接稳，不需要先自建完整的 Agent 运行框架。

“本地 CLI”表示执行入口在本机，不代表它调用的模型完全离线。模型和登录方式继续继承各 CLI 的配置。

README 的“个人管家与学习工作台”与上述定位一致。后续功能以这个闭环排优先级，视频课件作为知识处理工具保留。

## 3. 对话中断：确认存在的取消路径

### 3.1 当前行为

`src/renderer/shell/Workspace.tsx:1062` 的 `stopActiveStreamForNavigation()` 在运行中调用 `cancelStream(activeAssistantId)`。

调用它的路径包括：

- 切换到另一段对话：`Workspace.tsx:1249`。
- 新建对话、清理草稿状态：`Workspace.tsx:1072`。
- 离开当前对话：`Workspace.tsx:1086`。
- 托盘或通知打开对话：`Workspace.tsx:442`。

尤其是“日常”入口：在已处于日常聊天时再次点击，部分路径会调用 `leaveConversation()`，进而停止生成。普通页面切换的 `changeSection()` 则没有直接调用取消，不能把所有导航都说成必然中断。

另一个独立机制是 CLI 默认的 180 秒请求总超时：`src/main/agent/cli-agent-client.ts:122`。当前总计时器到点就终止进程，持续输出也不会重置它。长规划可能因此被打断，但没有日志证据证明昨天遇到的就是超时。

### 3.2 目标行为

- 点击今日安排、长期计划、知识库、设置、其他对话，原回复继续生成。
- 返回原对话，立即看到已生成的内容和当前步骤。
- 停止按钮只停止当前会话对应的运行，不影响其他会话。
- 运行结束时，侧栏显示完成标记；中断时说明原因。
- 退出应用时保存已收到的文字和运行状态。重新打开后显示“已中断”，不会假装仍在运行，也不静默重做有副作用的操作。

### 3.3 建议实现

把“对话运行”从 `Workspace.tsx` 的局部状态提升到主进程会话运行管理器：

```text
ConversationRun
  runId
  conversationId
  providerSessionId?
  status: starting | running | waiting | completed | cancelled | failed | interrupted
  lastEventSequence
  startedAt / lastActivityAt
  partialAnswer
  publicSteps
  errorReason?
```

渲染进程只订阅、读取、展示，页面导航不改变运行状态。每条事件带 `runId + conversationId + sequence`，重订阅时补齐遗漏事件，防止串到其他对话。

运行中的对话不直接删除；删除操作先明确处理该运行。第一版允许多段对话存在，CLI 执行可以先排队，界面显示“排队中”，不必立即做无限并行。

超时拆成“启动等待”“无活动等待”“总时长上限”三类。输出、工具进度更新最近活动时间；等待用户输入有单独状态。界面区分“用户停止”“超时”“CLI 退出”“网络错误”。

这项应先做，单纯删掉导航里的 `cancelStream` 会留下跨会话状态、停止按钮和结果刷新问题。

## 4. 工作过程：解决“有思考，但感觉不到”

### 4.1 当前的三处缺口

1. `src/renderer/shell/TraceFlow.tsx:51` 默认 `open=false`。有内容后仍默认收起，只露一行摘要；正文为 12px 灰字，正在执行时不够醒目。
2. `src/main/agent/model-client.ts:84` 附近的 `ModelStreamEvent` 只有 reasoning 和 text。CLI 原生工具执行缺少统一事件类型。
3. Claude 解析主要处理 `content_block_delta` 和最终 result；Codex 解析主要处理 `item.completed` 中的 reasoning、agent_message 和 error。原生工具的开始、执行进度、文件变更等没有完整转给管家层。ASAKI 自己的工具循环虽然有 tool-start/tool-result，但不能代替 CLI 原生事件。

证据位置：

- `src/main/agent/cli-agent-client.ts:964` 附近的 Claude 事件处理。
- `src/main/agent/cli-agent-client.ts:1001` 附近的 Codex 事件处理。
- `src/main/butler/butler-service.ts:293` 附近的事件转发。

### 4.2 展示原则

重点展示实际发生的工作：参考了什么、当前做什么、改了什么、结果在哪。

模型实际返回的推理摘要可以展开查看；模型没有返回时，展示执行状态和工具事件。不生成假的“思考文字”，也不承诺展示模型未公开的内部推理。

### 4.3 建议的体验

运行中默认展开一个工作过程区：

```text
正在为你安排本周任务 · 已运行 18 秒
✓ 读取目标：准备英语考试
✓ 参考个人约束：工作日每天 1 小时
✓ 查看本周已有任务
● 正在拆分每日安排
○ 等待保存结果
```

其中带勾的项只在相应读取或执行成功后出现，不能预先编造。预计步骤和实际步骤使用不同状态。

- 进行中显示当前步骤、已完成项和耗时；长文本限制高度，可主动展开。
- 回答开始后压缩成“参考 3 项资料，完成 2 项操作”，保留查看过程的入口。
- 用户手动展开后尊重其选择，不因每次新事件反复折叠。
- 结束后给出结果入口：“查看长期计划”“查看今日任务”“查看新增记忆”。
- 历史记录保存公开的步骤、来源和结果摘要；原始推理文本不作为永久个人记忆自动保存。

统一事件建议包含：status、reasoning-summary、assistant-text、tool-start、tool-progress、tool-result、artifact、usage、error、done。适配器只发送当前 CLI 实际提供的事件。

## 5. CLI 设置：继承本机配置

### 5.1 当前缺口

扫描器已能查安装路径、版本和登录状态，但模型发现只在帮助文本显示 models 能力后尝试执行 `models`：

- `src/main/agent/local-cli-discovery.ts:438`。
- 模型解析器只接受类似 `provider/model` 的文本：`local-cli-discovery.ts:359`。单段模型名、配置中的别名和自定义目录不能完整覆盖。
- 设置仍同时要求用户理解提供商、模型名、CLI agent、命令、原生工具、隔离模式和推理强度。

### 5.2 本机实际可用的信息源

| CLI | 已读取的模型信息 | 对 ASAKI 的意义 |
|---|---|---|
| Codex | `~/.codex/config.toml` 指定 `model_catalog_json = "magpie-models.json"`，当前模型为 `codex/gpt-6.1-sol` | 可以读取引用的模型目录，取得 slug 和显示名，不需要写死型号 |
| Claude Code | `~/.claude/settings.json` 使用 `sonnet[1m]`，Haiku/Sonnet/Opus 的环境映射指向同一个自定义模型 | 显示“继承 CLI 默认”和已配置别名；可补充实际映射说明 |
| OpenCode | `~/.config/opencode/opencode.json` 有默认 model 和 provider.models | 从配置与 CLI 返回结果合并模型候选 |

这些是“配置中发现的候选模型”，不等于逐个验证了账号权限、余额和远端可调用性。

### 5.3 建议的设置页

主界面只保留：

```text
本机 AI
  扫描结果：Claude Code / Codex / OpenCode
  当前使用：Codex
  模型：继承 CLI 默认 / 本机配置的模型列表
  推理强度：跟随 CLI / 可支持的档位
  [重新扫描] [测试连接]
```

- 第一次打开自动扫描，后续用缓存快速显示，并提供重新扫描。
- 下拉列表只来自本机有效配置、CLI 返回的目录和当前已配置项；展示模型来源。
- 没有列表时保留“继承 CLI 默认”，不让用户猜型号。
- 默认不传 `--model` 和推理强度覆盖参数；显式选择才覆盖。
- 同一份发现结果同时供设置页和聊天输入框使用。
- 命令路径、权限模式、配置作用域放进高级设置；API 接入保留为高级选项。
- Claude、Codex、OpenCode 分别实现配置适配器，不能假设所有 CLI 都支持同一个 `models` 命令。
- 读取模型字段时忽略凭据字段。配置解析失败回退到 CLI 默认，不覆盖原配置文件。
- 用户当前的模型配置不一致时保留原选项，并显示来源，不在保存设置时静默换模型。

Codex 的结构化服务可以作为后续适配方案，但先完成配置读取和默认继承，避免一次改掉全部会话协议。

## 6. 个人档案与知识库

用户所说的“个人映射”应包含：

- 身份与现状：当前工作、所处阶段、正在推进的目标。
- 偏好与约束：每天能投入多久、固定时间段、提醒方式、预算。
- 能力与经验：已经掌握的内容、做过的事情、常见卡点。
- 近期变化：最近完成的事、改变的目标、阶段性状态。

资料库、知识笔记继续保留，但和“关于我”的档案采用不同的数据含义。

### 6.1 当前基础

已有记忆类型是 weakness、strength、preference、plan、fact，已有资料库和 MiniSearch。可以在现有 Markdown 数据之上演进。

管家上下文目前优先取已掌握和最近更新的知识主题，最多 15 个；8 篇笔记每篇最多 240 字。系统提示中的任务最多 10 项、记忆最多 8 条：

- `src/main/butler/context.ts:30`。
- `src/main/butler/prompt.ts:35`。

这些截断本身合理，但目前选择逻辑并未充分按这次问题检索。资料多起来后，即使文件在本地，也不代表本轮对话参考了它。

### 6.2 建议

- 新增全局个人档案，项目记忆作为补充。生活偏好不必绑在“考研”等项目上。
- 每条记忆记录来源、时间、适用范围、有效状态，并区分“用户明确提供”与“模型推测”。
- 档案可查看、编辑、删除和标记过期；旧事实被替换时保留来源，避免互相矛盾。
- 对话先加载少量稳定档案，再用现有 MiniSearch 检索与当前问题相关的笔记、任务、计划和记忆。
- 先做关键词检索、项目过滤和相关性排序；需要时再评估向量检索。
- 对话里可见“本次参考”，点击可打开原记录。
- 用户明确要求“记住”时保存；模型对性格、能力等的推测作为候选，不能自动变成确定事实。

## 7. 从长期计划到今日提醒的闭环

当前 `Workspace.tsx:1318` 的 `addPlanDayToSchedule()` 把长期计划的一天复制成普通任务，传入标题、科目、时长、验收和日期，没有传稳定的计划条目来源标识。重复操作可能重复创建，也难以把今日完成结果回写给原计划。

建议建立：

```text
目标 → 阶段 → 周计划 → 计划条目
                         ↓ 稳定来源 ID
                     今日任务 → 提醒 → 完成记录
                         ↑              ↓
                         └── 复盘与重排 ──┘
```

- 每个任务关联 goalId、planId、planItemId；同一计划条目重复加入时返回已有任务。
- 在今日任务勾选完成后，更新长期计划进度，或通过同一条任务事实派生进度，避免两份状态互相漂移。
- 计划调整保留已完成记录，仅修改未执行的安排，展示变更摘要。
- 明确固定时间、预计时长、截止日期的区别，不能把“23:30 睡觉”作为普通顺序任务排到中午。
- 提醒记录待触发、已触发、已完成、延后和失败状态；跨重启验证幂等性与漏提醒处理。
- 时间到达与系统通知不依赖模型；模型不可用时仍能提醒，AI 只负责组织内容和调整建议。
- 桌面后台提醒要求应用或后台进程运行。休眠、关机、退出后的补提醒规则要写清楚，不承诺离线关机仍准时通知。

## 8. 页面布局建议

### 8.1 当前值得保留的部分

深浅色、统一的卡片和蓝色主色、可调侧栏、独立聊天区和今日时间表已经具备可用基础。

### 8.2 主要问题

- “今日安排、长期计划、日常、知识库、记忆、复盘、提醒”七个并列入口，加上工作区树，理解成本较高。
- “日常”和“新对话”都通向聊天，但作用不同，不容易预判点击后的会话变化。
- 首页的大面积空白只有欢迎语和输入框，缺少管家应主动呈现的今日重点、临近截止和待处理事项。
- 设置页是长卡片堆叠；预算、模型、备份、通知混在一条长页面里。
- 个人情况主要藏在“记忆”里，知识库看起来更像学习主题目录，缺少“阿咲了解我什么”的明确入口。
- 知识库空状态重复提示“没有主题”，但下一步导入或建立个人档案的路径不够清晰。

以上来自当前原型页面与组件结构，不是对真实个人资料内容的判断。

### 8.3 建议导航

```text
阿咲
  今日
  对话
  目标与计划
  我的资料
  知识库

项目
  按需展开具体项目与对话

底部
  通知中心 · 设置
```

提醒与复盘归入今日和目标流程，保留直接入口或子页；原数据不丢弃。“工作区”对用户称为“项目”，概念只出现一次。

### 8.4 建议页面

**今日**：置顶“现在最值得做的 1～3 件事”，接着是今日时间表、临近提醒、目标进度和一句话输入框。不能只让用户自己从任务总表里找重点。

**对话**：主区集中聊天；顶部显示当前项目、CLI、模型和运行状态；可折叠的右侧面板显示“本次参考”“已产生结果”。宽屏才显示右栏，窄屏用抽屉，避免四栏挤压正文。

**目标与计划**：每个目标显示下一步、进度和风险。长期计划、每日任务和复盘放在同一目标下，不要求用户跨多个页面核对。

**我的资料**：展示“关于我、偏好约束、能力经验、近期变化”，每项可以查看来源和更新时间。

**知识库**：保留目录和笔记正文；证据与关系按需展开。视频转课件放入资料处理工具区，不占据核心个人管家流程。

**设置**：按“本机 AI、提醒与后台、个人与外观、数据与备份”分组，默认展示普通用户需要的选项。

## 10. 实施优先级与验收

### P0：可靠对话

交付：导航不取消、运行独立管理、公开过程事件、明确的终止原因。

验收：

- 同一回复生成中依次打开今日、知识库、设置、另一对话，再返回，回复继续且不串消息。
- 点击停止只取消指定运行，保留部分输出和已执行结果。
- 关闭再打开应用，不出现永远“运行中”的残留状态。
- 有持续事件的长回复不会被当作无活动超时；进程退出和超时有不同提示。
- CLI 有真实工具事件时可看到开始和结果；没有推理摘要时不显示虚构内容。

### P1：本机 CLI 设置

交付：自动扫描、读取本地目录、默认继承、单一模型选择数据源。

验收：

- 本机 Codex 配置引用的目录可以显示模型名；支持重新扫描。
- Claude 别名与自定义映射可以显示，默认继承不被 ASAKI 覆盖。
- 配置损坏或列表为空仍可选择 CLI 默认；不伪称“没有模型”。
- 切换 CLI 不重置旧会话的历史和已有运行配置。
- 页面不需要填 API Key、命令和型号才能完成最常见配置。

### P2：个人映射和目标闭环

交付：全局个人档案、相关资料检索、来源可见、计划条目与任务关联、提醒闭环。

验收：

- 用户更新每天可用时间后，下次规划参考新值并展示来源。
- 重复加入同一计划条目不创建重复任务。
- 今日完成状态能反映到长期目标进度。
- 模型不可用时，已设置的时间提醒仍正常工作。
- 个人事实可纠错、过期和删除，不把模型猜测永久当作事实。

### P3：导航与首页

交付：今日概览、精简导航、对话上下文面板、设置分组。

验收：

- 打开应用就能判断下一步要做什么，以及最近有什么提醒。
- 1440×900 和 1366×768 下正文不被侧栏挤压；窄屏不强行并排三栏。
- 原有项目、笔记、计划、复盘和提醒均有入口。
