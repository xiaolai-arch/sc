# Study Coach（暂定名）设计文档

- 日期：2026-10-31
- 状态：设计已评审，待用户最终确认
- 目标：开源、本地优先的桌面 AI 私教

---

## 一页摘要

Study Coach 是一个跑在用户自己电脑上的 AI 学习教练。它替用户规划、督促、答疑，用户只负责执行。它的全部记忆是一个 Obsidian 兼容的 markdown 知识库，用户和 agent 共同维护——数据人类可读、可迁移、不锁定。

第一版聚焦考研（2027 年 12 月初试，约 14 个月周期），验证“agent 能否真的把一个人带到考场”这一件事。Agent 学习作为第二个领域包，架构上预留，v1 不做。

---

## 1. 背景与意图

用户正在准备考研，同时在学 agent。现有工具各有缺口：

- **通用聊天 AI**：没有长期记忆，不知道用户昨天学到哪、错在哪。
- **计划 / 待办工具**：不会根据执行情况自己调整，需要用户手工维护。
- **笔记软件**：不会主动教，也不会督促。
- **考研 App**：内容导向，不提供个性化的规划与一对一答疑。

用户想要的不是一个“更聪明的待办清单”，而是一个**住在电脑里的私教**：它知道目标、进度、薄弱点，自己决定今天学什么、什么时候提醒、怎么讲，用户只负责执行和反馈。

选择开源 + 本地优先的理由：

- 学习数据（笔记、错题、进度、对话）高度私密。
- 目标用户（学生）对订阅制敏感，自带模型 API key 成本可控。
- 开源能建立信任，也便于社区贡献领域模板。
- 作者的 14 个月备考周期，正好边做边用。

## 2. 目标、非目标、反目标

### 2.1 目标

1. 每天自动生成一份可执行的计划（3–5 个任务，含时长、材料、验收标准）。
2. 用户执行后，agent 知道结果，并在晚上复盘时自动调整下一步。
3. 主动督促：在合适的时间出现，而不是等用户打开聊天框。
4. 一对一答疑：基于用户的知识库和导入材料讲解、出题、判分、沉淀笔记。
5. 学习数据全部本地、人类可读、可迁移；卸载软件不丢数据。
6. 开源、自带模型 key、无需注册、无遥测。
7. 架构支持“领域包”，v1 内置考研包，后续可加 Agent 学习包。

### 2.2 非目标（v1 不做）

- 在线服务、账号系统、云同步、多设备同步。
- 移动端 App。
- 社交、排行榜、学习社区。
- 内容平台：不内置、不分发受版权保护的教材或真题。
- 通用聊天助手：只服务学习场景。
- 插件市场、可视化知识图谱。

### 2.3 反目标（做成这样就失败了）

- **变成需要用户手工维护的任务管理器**：用户只应执行，不应负责排计划。
- **黑盒记忆**：任何“它记得你”的内容都必须能在 vault 里以 markdown 看到。
- **焦虑制造机**：通过频繁提醒、羞辱式督促制造压力。
- **模型 / 格式锁定**：不能换模型、不能用 Obsidian 打开，都算失败。
- **过度自主**：未经确认删改用户手写笔记、代替用户标记完成。

## 3. 用户与核心场景

### 3.1 用户

- 主要：准备考研的学生。首版支持政治、英语、数学、专业课等科目，可自定义。
- 次要：有明确考试目标、愿意自己填模型 key 的学习者。
- 后续：学 agent 的开发者（第二个领域包）。
- 作者本人是第一位用户，所有功能先满足自己的日常使用。

### 3.2 一天的使用

- **早上**：打开 App，今日计划已生成。每个任务写明科目、时长、用什么材料、怎样算完成。
- **学习时**：点“开始”，番茄钟计时；任务完成后勾选并记录实际用时。
- **卡住时**：打开对话提问。Agent 读知识库和导入的材料来回答；讲完把要点沉淀成笔记或错题。
- **晚上**：App 弹出复盘（可关闭）。三个问题：完成了什么、卡在哪、明天怎么调。Agent 更新学习画像和明日计划。
- **周日**：生成周报和下周计划。
- **随时**：托盘显示今日进度和下一个任务；免打扰时段可配置。

用户只做三件事：**执行、回答、提问**。

## 5. 产品形态

- **桌面应用**：macOS 优先，架构跨平台（Windows/Linux 后续验证）。
- **常驻托盘 / 菜单栏**：后台运行，可主动发起提醒。
- **三个主界面 + 设置**：
  - **今日**：今日任务、计时器、完成情况、晚间复盘入口、本周进度。
  - **对话**：与教练对话；可引用笔记/材料；回答可一键归档。
  - **知识库**：文件树、markdown 编辑器、双链跳转、搜索、复习队列。
  - **设置**：模型与 key、提醒时段、语气、数据目录、导入材料。
- **首次启动**：Onboarding 向导，10 分钟内拿到第一周计划。

## 6. 知识库（vault）

### 6.1 格式

- 纯 markdown 文件 + YAML frontmatter + `[[wikilinks]]`。
- 目标是 Obsidian 可以直接打开同一个文件夹。
- **文件是唯一事实源**；SQLite 只做索引缓存，删除后可重建。

### 6.2 默认目录结构

```text
00-目标/
  考试档案.md          # 考试日期、目标院校/专业、科目、每日可用时间、当前水平
  总计划.md            # 分阶段计划（基础 / 强化 / 冲刺）
01-计划/
  周计划/2026-W44.md
  日计划/2026-10-31.md
02-日志/
  2026-10-31.md        # 执行记录、复盘、情绪/状态
03-知识/
  数学/...
  英语/...
  政治/...
  专业课/...
04-错题/
  数学/...
05-材料/
  教材/                # 用户导入的 PDF/文本，保留原文件
06-答疑/
  2026-10-31-主题.md
07-画像/
  学习画像.md          # 强项、弱项、节奏、偏好、历史偏差
```

目录名允许用户重命名；agent 通过 frontmatter 的 `type` 字段识别内容类型，不硬编码路径。

### 6.3 Frontmatter 约定

```yaml
---
type: note | mistake | plan | log | qa | profile | material
subject: math
status: draft | active | done | archived
created: 2026-10-31
updated: 2026-10-31
source: user | agent | imported
tags: []
review:            # 仅 mistake / note 使用
  next: 2026-11-02
  interval_days: 2
  ease: 2.5
---
```

### 6.4 共同维护规则

- **Agent 可直接写**：日志、日计划、答疑沉淀、错题、学习画像、周报。
- **Agent 修改用户手写笔记前**：展示 diff，用户确认后写入；或在文末追加“Agent 补充”区块，不改原文。
- **删除**：永不自动删除；移入 `.trash/`。
- **元数据 vs 正文**：frontmatter 的 `review.*`、`status`、`updated` 属于 agent 可维护字段，即使文件由用户手写也可直接更新；正文修改仍需 diff 确认。`source` 只表示最初创建者；用户用 Obsidian 等外部编辑后，文件监听标记 `user_touched: true`，此后正文修改一律需确认。
- **并发**：文件监听（chokidar）；写入前检查 mtime，发现外部修改则先合并/提示，不覆盖。
- **导入**：拖入 PDF/文本；提取文本供检索；原文件保留在 `05-材料/`；不做版权内容分发。

### 6.5 对话记录

- 所有对话以 markdown 持久化在 `06-答疑/对话/YYYY-MM-DD.md`，含用户消息、agent 回答、工具调用摘要；设置页可关闭持久化（关闭后只保留会话内上下文）。
- 原始对话不进 SQLite 独存；SQLite 只做索引，删除可重建。
- 这保证“它知道昨天问过什么”可被用户直接查看、搜索、迁移。

### 6.6 课程大纲与知识点（v1 已确认）

- `00-目标/考试大纲.md`：科目、考试代码（数学一/二/三、英语一/二）、参考书目、大纲来源。
- `03-知识/` 下按章节/知识点建 note，frontmatter 增加 `syllabus_id`、`coverage`、`confidence`。
- 计划只引用知识点，不凭空生成；公共课由领域包提供初始大纲，专业课由用户导入大纲/教材后由 agent 抽取。
- 领域包内容由作者用 AI 生成初稿、人工校对；公共课优先，专业课不做内置。
- v1 已确认采用该结构；M1 增加约 3–5 天。

## 7. Agent 设计

### 7.1 运行时

- 应用内置 agent loop（TypeScript），tool calling。
- 模型层多 provider：Anthropic、OpenAI、DeepSeek、Z.AI（OpenAI 兼容）、任意 OpenAI-compatible endpoint、Ollama。
- 每个角色可配置不同模型：
  - `planner`：强模型，负责计划与复盘。
  - `tutor`：强模型，负责讲解与出题。
  - `grader`：便宜模型，负责判分、摘要、归档。
- 成本上限分两层：主动会话预算（默认每日 4 次）耗尽后停止主动调用；全局每日 token/金额预算耗尽后，用户手动发起的对话弹一次确认，确认后可继续，不静默拦截。
- 预算耗尽时，早晨计划降级为“昨日未完成任务 + 固定模板”，不调模型。

### 7.2 工具集（v1）

| 工具 | 作用 | 权限 |
|---|---|---|
| `vault.list` / `vault.search` / `vault.read` | 检索与读取知识库 | 只读 |
| `vault.write` | 写日志、笔记、错题、画像 | 分类型，见 §6.4 |
| `plan.get_today` / `plan.update_today` | 读取/调整今日计划 | 自主 |
| `plan.update_week` / `plan.update_master` | 修改周计划/总计划 | 需确认 |
| `log.append` | 追加执行记录 | 自主 |
| `quiz.create` / `quiz.grade` | 出题与判分 | 自主 |
| `material.read` | 解析导入的 PDF/文本 | 只读 |
| `reminder.schedule` / `reminder.cancel` | 安排本地通知 | 自主（受时段限制） |
| `profile.update` | 更新学习画像 | 自主 |
| `clock.now` | 当前时间 | 只读 |

### 7.3 自主循环与触发器

- **触发**：App 启动；每日固定时段（默认早 8:00、晚 21:30）；任务完成；用户长时间无活动；用户主动对话。
- **每日主动 LLM 会话上限**：默认 4 次；超出后只发本地规则提醒（不调模型）。
- **免打扰时段**：默认 23:00–07:30，可配置。
- **开机自启**：onboarding 中可选，默认开启托盘常驻。
- **错过触发**：Mac 休眠或 App 未运行时，下一次启动补生成（早上补计划、晚上补复盘），通知不补发，避免集中轰炸。
- 所有主动行为记录在当日日志，用户可查“今天它为什么找我”。

### 7.4 权限边界

- **可自主**：调整今日任务顺序/时长、选择复习内容、生成练习、安排提醒、写日志与画像。
- **需确认**：修改周计划/总计划、修改用户手写笔记、删除文件、导入大材料、切换模型。
- **禁止**：删除用户笔记；把数据发往用户未配置的模型；代替用户标记任务完成；替用户做报考决策。
- **待确认队列**：需要确认的主动变更写入持久化队列（`01-计划/待确认.md` 或 SQLite），通知用户；App 重启后仍在，未确认前不落盘；默认 7 天过期。

### 7.5 教学策略

1. **先诊断**：用 1–3 个问题或小测判断用户当前水平，不直接开讲。
2. **基于材料**：优先引用用户导入的教材/真题和已有笔记；明确标注来源。
3. **讲完就练**：讲解后立即出 1–3 道题；用户答完再判分。
4. **复述检验**：让用户用自己的话复述，agent 找漏洞。
5. **沉淀**：每次答疑生成/更新一条笔记，链接相关知识点；错题进入复习队列。
6. **复习调度**：简化版 SM-2（next / interval_days / ease），答对延长、答错缩短。

### 7.6 督促策略

- 每个任务必须能在 5 分钟内开始，降低启动成本。
- 未完成时不斥责：记录原因，缩小或调整任务；连续未完成则先问“卡在哪”。
- 语气可配置（温和 / 严格），默认温和但坚定。
- 周报只陈述事实与下一步，不做道德评价。

## 8. 技术架构

```text
┌────────────────────────────────────────────┐
│ Electron App                                │
│  ┌──────────────┐      ┌─────────────────┐ │
│  │ Renderer      │ IPC  │ Main Process    │ │
│  │ React + TS    │◄────►│ 文件系统 / 托盘  │ │
│  │ 今日/对话/知识库│      │ 本地索引 / 调度器 │ │
│  └──────────────┘      │ Agent Runtime   │ │
│                         │  ├─ LLM Provider │ │
│                         │  ├─ Tools        │ │
│                         │  └─ Scheduler    │ │
│                         └─────────────────┘ │
└────────────────────────────────────────────┘
          │
          ▼
   本地 vault（markdown 文件夹，Obsidian 兼容）
```

- **Electron + React + TypeScript + Vite**：跨平台、生态成熟，与作者现有 Node 工具链一致。
- **主进程**：文件系统、SQLite（FTS5 索引）、托盘/通知、调度、PDF 解析、agent 运行时。
- **渲染进程**：三个主界面；通过 IPC 调用主进程能力。
- **模型层**：Vercel AI SDK（多 provider 统一接口）。
- **密钥存储**：Electron safeStorage（macOS Keychain 支持）；不写入明文配置。
- **索引**：v1 用 MiniSearch 做本地全文检索（纯 JS，无原生模块）；数据量增大后可换 SQLite FTS5；v1 不做向量检索。
- **文件监听**：chokidar。
- **打包**：electron-builder；v1 手动下载更新，不做自动更新。
- **遥测**：无。错误日志仅存本地，用户可手动导出。
- **测试**：计划生成、复习调度、vault 读写、权限边界用单元测试；关键流程少量 e2e。

## 9. UI / UX 要点

- **中文优先**。
- **Today 页**：任务卡片（科目、建议时长、材料、验收标准）、开始/完成/跳过、番茄钟、今日进度。v1 是任务清单 + 建议时长，不排具体时间点，也不做日历时间块。
- **对话页**：消息流、引用 chips（笔记/材料）、工具调用可见但可折叠、回答可归档。
- **知识库页**：文件树、CodeMirror 编辑器、预览、双链跳转、搜索、复习队列。
- **复盘弹窗**：晚间触发，三个问题，可跳过；跳过也记录。
- **托盘**：今日进度、下一任务、快捷开始、免打扰开关。
- **空状态**：首次使用一键生成第一周计划；没有材料时允许纯对话答疑。

## 10. 安全、隐私与数据

- 默认无账号、无服务器、无遥测。
- 数据目录用户可选；默认 `~/Documents/StudyCoachVault`（或 App 数据目录）。
- 发送给模型的内容：当前对话、检索到的相关笔记片段、任务上下文。设置页明确列出“哪些数据会发给模型”，并支持本地模型完全离线。
- API key 只存本机安全存储；日志中脱敏。
- 导入材料仅本地解析；不上传到除模型调用外的任何地方。
- 删除走 `.trash/`；提供“导出全部数据”为普通文件夹。

## 12. V1 范围与里程碑

### 12.1 必须有

1. Onboarding：考试日期、科目、每日可用时间、当前水平 → 总计划。
2. Vault：目录结构、读写、文件监听、搜索。
3. 每日计划 + 晚间复盘（闭环核心）。
4. 对话答疑 + 工具调用 + 回答归档。
5. 错题与复习队列。
6. 托盘常驻 + 主动提醒 + 免打扰。
7. 模型设置（多 provider、key、成本上限）。

### 12.2 暂不做

知识图谱、移动端、云同步、插件市场、多用户、语音、Agent 学习包、网络资料自动抓取、自动更新。

### 12.3 里程碑（粗略估计，非承诺）

- **M1（3–4 周）**：vault + onboarding + 每日计划/复盘，能自己每天用。
- **M2（3–4 周）**：对话答疑 + 工具调用 + 错题复习。
- **M3（2–3 周）**：托盘/通知 + 打包 + 开源发布 v0.1。
- **之后**：dogfood 一个月，根据真实使用迭代；再考虑第二个领域包。

已确认做轻量大纲模型（§6.6），M1 增加约 3–5 天。

作者同时备考，里程碑按可用的业余时间调整。

## 13. 成功标准

1. 作者本人连续使用 4 周，每日计划完成率可追踪。
2. 新用户 10 分钟内完成 onboarding 并拿到第一周计划。
3. 所有学习数据可在 vault 中查看、编辑、迁移；卸载软件后数据仍在。
4. 主动调用成本可配置且有硬上限；超限时功能降级而非报错。
5. 开源发布后，陌生人能按 README 在 15 分钟内跑起来。
6. 答疑回答能引用用户自己的笔记/材料，而不是泛泛而谈。

## 14. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 执行数据靠自报，可能不准 | 计划调整失真 | v1 接受；用计时器与复盘问题提高质量；后续可接 Anki/日历 |
| 模型质量参差 | 教学效果不稳定 | 推荐模型清单；按角色分配模型；失败降级 |
| 计划质量依赖考试信息 | 计划不靠谱 | 模板 + 对话式修正；总计划分阶段，允许滚动调整 |
| token 成本失控 | 用户不愿用 | 每日预算、主动会话上限、便宜模型做批改/摘要 |
| 范围蔓延 | 做不完 | v1 严格五件事；领域包后置 |
| 隐私顾虑 | 用户不敢用 | 本地优先、无遥测、明确数据流向、支持本地模型 |
| 版权 | 法务风险 | 不内置/不分发教材；只处理用户导入材料 |
| 开源维护成本 | 弃坑 | v1 单作者可维护；文档与测试优先 |

## 15. 决策确认（2026-10-31）

用户确认：

1. v1 做轻量结构化课程大纲/知识点（§6.6）。
2. 每日计划为任务清单 + 建议时长，不排具体时间块；日历/时间块后续版本再考虑。
3. 模型默认走用户自填的云端 API，可选 Ollama；不要求默认完全离线。

已按默认处理、不再阻塞：第一版只做考研；macOS 优先；v1 不做多设备同步；语气默认温和但坚定；v1 不主动联网检索资料。

后续版本再议：Windows/Linux 首发、多设备同步、知识图谱、移动端、Agent 学习领域包、语音。
