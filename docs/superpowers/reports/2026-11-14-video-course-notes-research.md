# 视频课程笔记与演示 HTML：开源项目调研

- 日期：2026-11-14
- 状态：调研完成，尚未选型定稿，未安装或实测任何候选项目
- 关联需求：用户手动选择本地网课视频，生成课程 Markdown 笔记，以及像 PPT 一样逐页讲解知识点的 HTML 课件

## 1. 背景与目标

阿咲目前已经具备管家对话、长期计划、今日安排、复盘、记忆、知识库和练习系统，但所有学习资料的起点都是文字或用户手动记录。新增能力的起点是一段本地视频：

1. 用户选择一个本地视频文件。
2. 阿咲理解视频中的讲解、画面和结构。
3. 生成可沉淀进 vault 的 Markdown 课程笔记。
4. 生成一个像 PPT 一样分页讲解知识点的 HTML 课件，帮助用户理解而不是只做文字转写。

用户已确认接受把音频和关键截图交给云端 AI 处理，因此第一版不强制要求全本地运行。

## 2. 调研范围与判定标准

调研关注四类能力：

| 能力 | 说明 |
| --- | --- |
| 视频理解 | 本地视频导入、音频转写、关键帧/幻灯片抽取、时间轴对齐 |
| 笔记生成 | 结构化 Markdown、来源可追溯、可写入 Obsidian 风格知识库 |
| 演示生成 | 生成分页幻灯片，优先可直接离线打开的 HTML |
| 桌面集成 | 能否作为依赖或设计参考接入 Electron + React + TypeScript 应用 |

判定标准：许可证是否允许分发、维护活跃度、是否支持本地视频、是否具备可借鉴的完整流程，以及接入成本是否明显高于自建。

## 3. 候选项目

> 以下信息来自各项目官方 README 与许可证页面（2026-11-14 核对），未做本地安装和效果实测。star 数为调研时的近似值。

### 3.1 BiliNote

- 仓库：<https://github.com/JefferyHcool/BiliNote>
- 许可证：MIT
- 约 7.7k stars，Python 后端 + Vue 前端，另有 Tauri 桌面端

官方 README 列出的相关能力：

- 支持 Bilibili、YouTube、本地视频、抖音、快手。
- 本地音频转写，可选 faster-whisper、mlx-whisper、Groq、BCut。
- 支持多模态视频理解，生成结构化 Markdown 笔记。
- 可自动截取视频画面并插入笔记。
- 生成内容可关联原视频时间点。
- 任务历史、多版本记录、基于笔记的 RAG 问答。

**可借鉴**：本地视频导入、转写、截图、笔记生成、任务进度与失败重试的完整链路。

**接入判断**：不建议整套嵌入。它自带 FastAPI 后端、SQLite 存储和前端体系，会与阿咲现有设置、知识库和 vault 数据模型重复；它主要解决笔记生成，不提供教学型 HTML 课件。

**结论**：视频笔记部分的主要参考项目。

### 3.2 lecture-to-notes

- 仓库：<https://github.com/drpwchen/lecture-to-notes>
- 许可证：MIT
- 约 116 stars

该项目把讲座/课程录制转成有出处、可核对的笔记：

- 本地 Whisper ASR、抽帧、OCR 和本地视觉模型负责证据收集，LLM 只负责最后的成文。
- 笔记中的每条要点可关联转写时间点和当时屏幕上的幻灯片。
- 输出 Markdown，可导入 Obsidian 风格 vault。
- 额外生成一个视频、时间戳转写和摘要联动的 HTML 阅读页面。
- 强调隐私：`LECTURE_LOCAL_ONLY=1` 可阻止任何云端上传；默认不会在本地与云端之间静默回退。

**可借鉴**：最重要的原则是“生成的知识点应能追溯到老师何时说了什么、展示了什么”，而不是让模型自由发挥。

**接入判断**：它的 HTML 是同步阅读器，不是 PPT 式逐页课件。作者主要在 Windows + NVIDIA 环境验证，macOS 路径未经充分测试；部分导出流程默认移动原视频，阿咲接入时必须明确保持原视频不变。

**结论**：时间轴、来源引用和内容可信度设计的主要参考项目。

### 3.3 reveal.js

- 仓库：<https://github.com/hakimel/reveal.js>
- 许可证：MIT

HTML 幻灯片框架，本身不负责 AI 生成。官方 README 列出的能力包括分页/嵌套幻灯片、Markdown、Auto-Animate、演讲者备注、PDF 导出、LaTeX 和代码高亮。

**接入判断**：适合作为 HTML 课件的渲染底座。由阿咲生成经过校验的课件结构，再由固定模板渲染成 HTML，而不是让模型自由生成整页 JavaScript，这样版式和内容更可控。离线打开需要把脚本、样式、图片和公式资源一起打包，不能依赖 CDN。

**结论**：HTML 课件的首选直接依赖。

### 3.4 Presenton

- 仓库：<https://github.com/presenton/presenton>
- 许可证：Apache-2.0
- 约 11.8k stars

开源的 AI 演示文稿生成器和 API：

- 从提示词或上传文档生成演示文稿。
- 内置模板，支持 HTML + Tailwind 自定义模板。
- 可编辑 PPTX、PDF 导出。
- 支持 OpenAI、Anthropic、Gemini、Ollama 等多种模型供应商。
- 提供 Docker、API、Electron 桌面端和 MCP server。

**可借鉴**：大纲 → 页面内容 → 模板渲染的分层生成方式，以及生成后的编辑体验。

**接入判断**：完整应用包含 Next.js、Python/FastAPI 等较重的服务层，且不负责本地课程视频理解。第一版直接集成的成本明显高于收益；若后续需要可编辑 PPTX，可再重点评估。

**结论**：产品设计和后续 PPTX 导出能力的重要参考。

### 3.5 AI-Media2Doc

- 仓库：<https://github.com/hanshuaikang/AI-Media2Doc>
- 许可证：MIT
- 约 4.1k stars

将音视频转成小红书、公众号、知识笔记、思维导图、内容总结等风格的文档：

- 前端使用 FFmpeg WASM，无需本地安装 FFmpeg。
- 根据字幕信息智能截图并插入文章，无需视觉大模型。
- 支持自定义 prompt、字幕导出和针对视频内容的二次问答。

**接入判断**：图文笔记生成流程值得参考。但阿咲是桌面应用，长视频处理优先评估原生 FFmpeg，不必照搬浏览器端 WASM 方案。

**结论**：图文笔记与截图插入的次要参考。

### 3.6 Slidev

- 仓库：<https://github.com/slidevjs/slidev>
- 许可证：MIT

Markdown 驱动的开发者幻灯片工具，基于 Vue 3 + Vite，支持代码高亮、公式、Mermaid、交互组件和 PDF/PNG/PPTX 导出。

**接入判断**：如果第一批课程以编程内容为主，Slidev 很有吸引力；但它会引入 Vue/Vite 课件构建链，与阿咲现有 React 技术栈不同。第一版使用 reveal.js 更轻。

**结论**：备选方案，取决于课程类型。

### 3.7 faster-whisper

- 仓库：<https://github.com/SYSTRAN/faster-whisper>
- 许可证：MIT

基于 CTranslate2 的 Whisper 重实现，官方称同等精度下比 openai/whisper 快最多 4 倍，支持词级时间戳和 Silero VAD。

**接入判断**：可作为后续“本地转写”选项。第一版用户已接受云端处理，不必强制安装 Python 和下载模型。

**结论**：第二阶段本地化选项。

### 3.8 FFmpeg

- 官网：<https://ffmpeg.org/>
- 许可证：依编译选项不同，可能为 LGPL-2.1+ 或 GPL

用于读取媒体信息、抽取音轨和关键帧。**分发前必须单独核查所用二进制启用的编译选项和对应许可证义务**，不能只看官网首页。

**结论**：技术上必要，许可证策略需要在打包阶段确认。

## 5. 对阿咲的推荐组合

| 环节 | 推荐路线 |
| --- | --- |
| 视频处理 | 原生 FFmpeg/ffprobe：媒体信息、抽音轨、抽帧 |
| 语音转写 | 第一版接云端 ASR，保留可替换接口 |
| 画面理解 | 视觉模型分析筛选后的课件/板书截图，而不是上传每一帧 |
| 课程理解 | 转写与截图按时间关联后，再整理成知识结构 |
| 笔记 | Markdown，写入现有 workspace 与知识库体系 |
| HTML 课件 | 结构化课件内容 + reveal.js + 固定教学模板 |
| 本地处理选项 | 第二阶段接 faster-whisper |

关键原则：

1. **听懂与看懂结合**：只转写会漏掉没念出来的公式、图表和代码；只抽帧会漏掉口头解释。
2. **笔记和课件共用同一份课程结构**：避免两者内容不一致。课件应拆解概念、步骤、例题和易错点，而不是把长笔记切页。
3. **区分课程原意与 AI 补充**：关键内容保留来源时间点；额外类比和补充例题明确标注；识别不清的公式或术语提示核对，不静默编造。
4. **长任务可恢复**：分阶段处理、缓存中间结果、支持取消和重试；改课件不重复付费转写整段视频。
5. **复用本地知识库**：笔记、截图和课件放入 vault 并进入备份；原视频默认不移动、不修改。
6. **课件隔离**：导出的 HTML 不依赖在线资源；应用内预览不能获得 Electron 的文件读写、密钥等高权限接口。

## 6. 现有代码接入点与缺口

以下为仓库代码扫描结果（2026-11-14）：

### 6.1 模型能力

- `ModelMessage.content` 目前只有字符串，没有图片/音频输入协议：`src/main/agent/model-client.ts:16`、`:111`。
- AI SDK 的消息映射也只处理文本：`src/main/agent/ai-sdk-client.ts:178`。
- 本地 CLI 能力扫描即使识别到 images 标签，也未接入消息内容。
- 仓库内未发现抽音轨、抽帧或云 ASR 实现。

**结论**：需要新增 ASR 客户端、视觉输入适配和相应设置项；“现有聊天模型配置可用”不等于“现有转写能力可用”。

### 6.2 文件选择与 IPC

- 原生选择器目前只用于备份目录：`src/main/index.ts:200`。
- IPC 通道、参数校验和 bridge：`src/main/ipc.ts:65`、`:964`、`:1236`。
- preload 已统一代理，通常无需新增预加载机制：`src/preload/index.ts:4`。
- 公共接口契约：`src/shared/ipc.ts:198`。

**结论**：可仿照备份选择器增加视频 `openFile`，但课程任务需要独立的请求/事件通道。

### 6.3 笔记与知识库

- 已有 Markdown 原子落盘和相对 vault 路径：`src/main/workspace/create-workspace-service.ts:540`。
- 知识主题创建和主题笔记可复用。
- 自动关联目前只匹配笔记标题/tags 中已存在的主题，不抽取正文，也不会自动创建主题：`src/main/knowledge/create-knowledge-service.ts:346`、`:389`、`:618`。
- 课程笔记应先确认/创建主题，再链接笔记；不应自动标记为“已掌握”。

### 6.4 资源与展示

- 笔记全文已进入搜索：`src/main/search/documents.ts:171`。
- HTML 和图片没有对应的搜索索引或资源 API。
- 现有笔记预览是纯文本：`src/renderer/shell/Workspace.tsx:1932`。
- 备份/恢复会递归复制 vault：`src/main/backup.ts:112`、`:351`；vault 外的原视频不会自动备份。

**结论**：截图和课件应放在 vault 内并使用相对链接；需要新增课件预览组件和资源路径解析。

### 6.5 长任务

- 聊天流已有 requestId 事件、`AbortController` 和取消/退订机制：`src/main/ipc.ts:1173`、`:1208`、`:1349`。
- 模型 SDK 已传递 `abortSignal`。
- 但这是内存中的聊天流，不是持久任务队列。

**结论**：课程任务需要新增阶段进度、失败重试/恢复状态，以及媒体子进程的取消处理。

### 6.6 建议的最小接入方式

- 新增独立课程服务，建议目录 `src/main/courses/`，在 `src/main/context.ts:285` 组合。
- 前端使用独立的导入弹窗和课件预览组件，挂到项目记录区，避免继续扩写聊天大壳。
- 补充离线媒体/ASR 假实现、任务取消和重复落盘测试。
- 需要同步扩展：
  - `tests/main/ipc-preload.test.ts:184`
  - `tests/main/backup.test.ts:53`
  - `tests/renderer/project-page.test.tsx:164`
  - Web 原型的 mock API：`web/mock-api.ts:1737`

## 7. 风险与待验证项

1. **识别质量**：中文课程、口音、专业术语、公式和代码的转写与截图理解尚未实测。
2. **成本**：长视频的 ASR 和视觉调用费用需要估算，并接入现有 token 预算。
3. **许可证**：FFmpeg 二进制和任何随包分发的模型/资源需要在打包前逐项核查。
4. **隐私**：用户已接受云端处理，但设置页必须明确说明哪些内容会上传、上传到哪个供应商。
5. **课程类型差异**：数学推导、编程演示、纯口述理论对抽帧和课件结构的要求不同，需要先确定第一批样片。
6. **平台差异**：ffmpeg 子进程、路径和编码在 Windows 上需要单独验证。

## 8. 结论与下一步

没有必要从零实现所有底层能力，也没有一个已核实的开源项目能完整覆盖“本地视频 → 可信笔记 → 教学型 HTML 课件 → 阿咲知识库”这条链路。

推荐路线：

- 以 **BiliNote** 和 **lecture-to-notes** 作为视频处理与来源可信度的参考。
- 以 **reveal.js** 作为 HTML 课件的直接渲染底座。
- 以 **Presenton** 作为后续演示编辑与 PPTX 导出的参考。
- 将功能作为独立的“课程资料生成”模块接入，而不是聊天框里的一个上传按钮。

下一步需要补齐设计文档，明确：

1. 第一批课程类型与样片。
2. 云端 ASR 与视觉模型的具体供应商和降级策略。
3. 课程结构 schema（概念、步骤、例题、易错点、来源时间点）。
4. 课件模板、导出包结构和应用内预览的权限边界。
5. 分段、缓存、取消、重试和预算控制的具体行为。
