## 4. 覆盖率说明

`package.json` 没有 coverage 脚本，也没有 `@vitest/coverage-v8`；离线安装失败（`ENOTCACHED`），按任务约定**跳过覆盖率百分比**，改用 import 图盘点 `src/main/**` 的测试触达。口径：

- **直接引用** = 有测试文件 `import` 该模块或 `import` 会 re-export 它的 barrel。
- **间接执行** = 测试经由其它模块（如 `create-workspace-service` → `seed`）在运行期执行到它，但没有针对它的断言。

`src/main/**` 共 **108** 个模块，**90** 个有测试直接引用，**18** 个没有：

## 5. 建议下一步（按优先级，至多 5 条）

1. **给 `scheduler/delivery-log.ts` 补真实实现的测试（含跨日与损坏文件）。** 现在的“重启后不重复打扰”是产品对用户的明确承诺（CHANGELOG「提醒生命周期」），但所有调度器测试都注入假 `deliveryLog`，真实的 `createDeliveryLog`/`parse` 一次都没跑过；`parse` 的损坏回退与“只记当天”的语义全靠读代码确认。
2. **给 `fs/rename.ts` 的重试补测试。** 所有原子写入都经过它；Windows 上 `EPERM/EACCES/EBUSY` 的 20 次重试是本仓库唯一为 Windows 文件锁写的兜底，而 CI 的 Windows job 也只是间接经过，失败会被吞进别处的写入测试里，定位成本高。
3. **让 e2e 覆盖「我的资料」页与「更严的掌握判定」开关。** 6 个 spec 里唯一从未点击的导航目的地是「我的资料」（`profile`），而它承载了跨项目档案；设置页的「更严的掌握判定」勾选也只有 renderer 单测（`settings.test.tsx`、`practice-ui.test.tsx`），checkbox 保存 → 错题本/复习单提示出现的整条链路没有端到端证据（`e2e/` 中无任何一处出现该文案）。
4. **去掉 5 个 spec 里硬编码的默认称呼 `xiaolai`。** `settings/defaults.ts` 的 `displayName` 一旦改名，5 个 spec 的问候语正则同时失效；应从共享默认值导出后再匹配，避免一次改动造成批次性失败。
5. **把 `memory/profile.ts` / `records.ts` / `synthesize.ts` 的解析规则从“只有间接执行”提升为直接断言。** 这三者决定了记忆文件的读写格式与重复事实合并，目前只靠 `memory-service.test.ts` 间接覆盖，改格式时容易只修好服务层而漏掉解析分支。
