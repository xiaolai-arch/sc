# Legacy 对照期边界（item 61 Agent Runtime，2026-11-28）

> 定位：这是**对照期已知边界**，不是缺陷清单。Legacy 引擎在对照期内保持与现有
> 管家一致的直执行语义——用户读到的应当是「现在这样为什么可以接受、什么时候会
> 变」，而不是「这里有问题」。统一治理（审批、去重、预算、多项目范围）由
> Runtime/Pi 在网关上兑现；对照期结束（生产聊天流切到 RunController 并通过
> 观察期）后，本文件所列边界随之消失。

## 四条边界

### 1. 确认级工具在 Legacy 下没有审批

- 现状：Legacy 直执行路径上，「确认级」只是行为分级元数据；工具调用不经审批卡
  直接执行，唯一闸门是既有的「仅可查看 / 项目内修改」权限开关（与现有管家完全
  一致）。
- 为什么可以接受：对照期内生产聊天流就是现有管家本身，用户今天拥有的确认粒度
  不变、不多不少；Runtime 的三级行为与审批卡在引擎切换时整体生效，不会出现
  「一半审批一半不审批」的混合状态。
- 什么时候会变：生产聊天流切到 RunController 之后，确认级工具一律先弹审批
  （approval.requested → approved/rejected，一次批准绑定一次调用 + 一组参数）。

### 2. 无 committed-only 去重

- 现状：Legacy 路径上同一运行内重复发起相同写入（如同一句话触发两次
  create_task）不会被网关拦截；是否重复取决于模型行为本身。
- 为什么可以接受：现有管家今天就是这个行为；对照期没有引入新的重复面（工具表
  与执行体未变）。
- 什么时候会变：引擎切换后，网关对确认级调用做 runId + 工具 + 参数 + 范围的
  committed-only 去重，同参重复调用得到失败回执而不是二次写入。

### 3. `maxToolCalls` 预算不生效

- 现状：Legacy 直执行路径不消费运行预算；工具步数仍由既有 `maxToolSteps` 兜底
  （与现有管家一致）。`budget.maxModelCalls` 目前无消费方（见
  `src/main/runtime/contracts.ts` 的 F4 注记，item 71 处理）。
- 为什么可以接受：预算是 Runtime 引入的新约束，对照期本来就没有它——不存在
  「承诺了却不兑现」。
- 什么时候会变：预算消费接线（PiEngine 模型轮次入口 / LegacyEngine stream 包装
  处）随引擎切换批落地。

### 4. 多项目范围请求只取第一个项目

- 现状：Legacy 直执行按单项目语义运行（`ButlerService.stream` 的既有接口只接受
  一个 `workspaceId`），多项目范围的运行只对第一个项目生效。
- 为什么可以接受：现有管家的全部入口都是单项目；跨项目能力（如场景三的只读周
  总结 `weekly_review`）只在 Runtime 侧实现，只读不写，不产生歧义写入。
- 什么时候会变：多项目范围写入随引擎切换批显式设计（v2 方案确认），不在对照期
  内悄悄放开。
